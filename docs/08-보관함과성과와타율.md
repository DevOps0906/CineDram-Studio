# 08. 영상 보관함 · 성과 데이터 · 타율 (v8 / v8.1 / v9)

사용자가 전달한 화면 분석(영상 보관함, 스튜디오 성과, 강의 수치)을 설계에 반영한 문서다.
**수치는 전달받은 값이며 내가 검증한 것이 아니다.** 한 채널의 사례이고 목표값으로 쓰지 않는다.

## 1. 제작 모드 3종 (`jobs.exec_mode`)

사용자 명칭(2026-11-02): `auto_render` = 자동제작, `manual` = 캡컷으로 편집, `ai_assistant` = Aside 사용하기. 원클릭 폼의 "제작 방식"(구성)과 구분해 **제작 모드**로 부른다([docs/13 §16](13-원클릭제작흐름.md)).

| 값 | 방식 | 엔진 명령 | 맞는 때 |
|---|---|---|---|
| `manual` | 수동(캡컷 핸드오프) | `handoff` | 첫 편, 규칙 검증(정답 기준 확보) |
| `auto_render` | 자동 렌더 | `render` | 편수 증가, 재현성 |
| `ai_assistant` | AI 어시스턴트 위임 | `delegate` | 빠른 초안 + 사람 검수 |

- 같은 컷표.json 을 받는 **실행기 3종**이다. 판단은 규칙이 하고 어시스턴트는 실행만 한다(금지 블록: 컷 순서 변경·임의 삭제/추가·없는 장면 삽입).
- 방식 비교 기록: 컷 순서·개수 일치, 시각 오차, 사람이 고친 컷 수, 화자 중앙 정확도(컷별 O/X), 소요 시간, 어시스턴트가 임의로 바꾼 것 → `방식비교기록.json`, `job_events.human_edit`.
- 결과 재현성이 낮아 **사람 검수 필수**. 기능·버전에 종속되므로 파이프라인을 이 방식에 의존시키지 않는다(항상 수동/렌더로 되돌릴 수 있게).
- "어사이드(Aside)"는 **별도 외부 AI 도구**(사용자 PC에 설치하는 AI 브라우저 앱, https://aside.com/)다(2026-11-02 사용자 확정, 이전의 "캡컷 AI 기능" 가정은 철회). `ai_assistant`(`delegate`)에 대응한다. 넘기는 방법·결과 형식은 미확인([docs/13 §15](13-원클릭제작흐름.md)).

## 2. 영상 보관함

| 요소 | 설계 |
|---|---|
| 카드 | 썸네일·길이·제목·작품 코드·상태 배지(`공개됨` 등), 원본 없는 카드는 미리보기 불가 경고(sources 누락) |
| 탭·필터 | 카테고리(`works.category`) + 작품 필터 + 검색(제목·작품·소재 한 줄·대사) |
| "N종 흐름 보기" | `jobs.topic_id` 로 같은 소재의 구성 변형을 묶어 펼침 |
| 내보내기 | MP4(항상 병행) + 편집 프로젝트(캡컷/Pr). 프로젝트 파일은 버전이 바뀌면 깨질 수 있어 **MP4를 항상 같이 만든다**. v3의 "프로젝트 직접 생성 불안정" 판단은 "1순위 후보 + 매번 열어 확인 + MP4 병행"으로 수정 |
| 묶음 | 카드 1개 = MP4 + 프로젝트 + 지시서 + 자막 + TTS |
| 규모 | 3천 건급 → 지연 로딩, 페이지 조회, 캐시 먼저 보이고 백그라운드 동기화 |
| 보관 정책 | 원본·프로젝트·MP4별 보관 기간(디스크 부족 경고 대응) |

### 작품 코드 규칙 (전달받은 예시 해석 — 추정)
`ILTA_IL102_R2_20261101` = `작품약어_회차·소재번호_렌더버전_제작일`.
`outputs.work_code`, `render_ver`(다시 만들기마다 +1). 파일명에 넣어 검색·중복 방지·정리 기준으로 쓴다.

## 3. 업로드 게이트

| 단계 | 규칙 |
|---|---|
| 채널 연결 | 로그인 확인 전 예약 버튼 비활성 |
| 첫 업로드 | **반드시 사람이 승인** |

## 4. 레이아웃 L1 정정 (`layout_template`)

전달 자료 기준 하단은 **"핵심 대사 한 줄(빨간 박스) + `드라마 <작품명>` 표기"**.

| 필드 | 값 |
|---|---|
| 이름 | 예: `L1-제목2줄+하단작품표기` (구현: `hookingtime`) |
| 프레임 PNG·영상 창 크기와 좌표 | 크롭 계산의 **설정값**(추정값 대체) — PNG 를 받으면 `video.x/y/w/h` 확정 |
| 제목색 규칙 | 1줄 노랑 / 2줄 빨강(또는 흰색) |
| 채널별 매핑 | `channels.layout_template`, TTS 음성, 자막 스타일 |
| 핵심 대사 박스 | 지시서 후킹·펀치 대사에서 자동 추출 후보 — **미구현**(템플릿 슬롯만 예정) |

작품 표기는 출처 표기일 뿐 사용 허락이 아니다.

## 5. 제목 꼬리 4종과 A/B
`[역할] + [행동] + {~한 이유 / ~하면 생기는 일 / ~의 최후 / ~의 한마디}`. 꼬리별·`ㅋㅋ`유무별 성과를 성과 테이블에서 비교한다(같은 소재 2종, 같은 시간대).
무료판의 "기호 피하기"(C4-5)는 SHOULD 이고 실제 상위 영상은 `ㅋㅋ`·`ㄷㄷ`을 쓰는 경우가 있다 → **채널 스타일 층**(`rules/channel-hookingtime.md`)에서 옵션으로 두고 A/B 로 확정한다.

## 6. 성과 데이터

| 항목 | 설계 |
|---|---|
| `performance` | 영상별 조회수(**7일 / 28~30일 / 누적**), 예상 수익, 평균 시청 지속, 게시일. **`views_at`, `revenue_at` 이중 타임스탬프** |
| 수익 지연 | 같은 영상에서 조회수는 올랐는데 수익이 그대로인 사례(전달 자료) → 수익은 반영이 늦다. 1,000회당 단가는 **조회·수익 기준 시점이 같을 때만** 계산. 최근 7일 구간은 항상 과소 집계 취급 |
| 수집 주기 | 조회수 자주 / 수익 하루 1회. 스튜디오 Analytics API 또는 CSV (스크린샷은 임시) |
| 단가 | 전달값 약 160~180원/1,000회(편차 138~212). 사업 계획은 **평균**을 쓰고 고점 일수익(최고점)은 쓰지 않는다. 월 추정은 단가가 안정된 구간 기준 |
| 작품별 집계 | 작품 합계, 소재 수, 평균 조회수 → 진입 성적표(GO/NO) 근거 |
| 결 태그 × 성과, 템플릿 × 성과, 제목 꼬리 × 성과 | 성적표 지표 |

## 7. 타율 (v9)

"기획점을 넣으면 타율이 오른다"는 주장은 전달 화면만으로 **인과 확인이 안 된다**(선택 편향, 게시 후 경과일 혼재, 적용 전 비교 없음). 우리 시스템에서 직접 측정하게 만든다.

### 데이터
| 테이블/필드 | 내용 |
|---|---|
| `planning_points` | id, 이름, 설명, 그룹(소재/후킹/제목/구성/채널 스타일), 도입일 |
| `job_planning_points` | 작업에 적용된 기획점(체크한 것만) |
| `jobs.rule_version` | 만들 때의 규칙·템플릿 버전 |
| `hit_thresholds` | 타석 기준(예: 7일 10만=안타, 30만=2루타, 80만=홈런) — **채널 첫 10편으로 정하고 임의 값으로 고정하지 않는다** |

### 지표
| 지표 | 정의 |
|---|---|
| 타율 | 기준을 넘은 영상 ÷ 올린 영상 (**게시 후 같은 일수**로 비교, 예 7일) |
| 장타율 | 안타/2루타/홈런 비율 |
| 기획점별 타율 | 적용 영상 vs 미적용 영상 |
| 규칙 버전별 타율 | v1 → v2 변화 |
| 작품·템플릿·제목 꼬리별 타율 | 진입 성적표 근거 |
| 수익 | 28일 합계 / 일평균 / 고점 분리 |

평균은 대박 1~2편에 끌려간다(전달 표본: 평균 약 28만 vs 중앙값 약 14만). **중앙값과 타율을 함께** 본다.

### 검증 순서
1. 지금까지 올린 영상으로 "적용 전" 기준선(스튜디오 CSV). 2. 이후 영상마다 기획점 체크(작업당 1분). 3. 20~30편 후 기획점별 비교, **10편 미만이면 결론 보류**. 4. 효과 있는 것만 `rules/`에 고정. 5. 제목 꼬리·`ㅋㅋ`는 같은 소재 2종 A/B.
시트 한 장(영상, 적용 기획점, 7일 조회수)만으로도 시작할 수 있다.

### 기획점 초안 (규칙에서 가져옴)
| 그룹 | 기획점 | 규칙 |
|---|---|---|
| 소재 | 무시→쌓임→뒤집힘이 한 회차에 있다 | C1-2, D1-1 |
| 소재 | 기승전결마다 킥이 있다 | C1-4 |
| 후킹 | 0~2초에 얼굴 + 긴장 있는 소리 | C3-2 |
| 제목 | 역할로 쓰고 결과를 숨긴다 | C4-1, C4-4 |
| 구성 | 끝이 펀치 끝음절 + 당한 얼굴 | C6-1, C6-2 |
| 소재 | 갈등 유형: 누명·오해 / 들킬 위기 / 선택의 기로 | common §1 |
| 소재 | 작품 매력: 신작 / 명작 / 스타 | common §1 |
| 제목 | 정답을 숨긴 제목(상황은 보이고 결과는 숨김) | C4-1 |
| 채널 스타일 | 제목 `ㅋㅋ/ㄷㄷ` 유무 | A/B |
| 역사 다큐용 | 전환에 새 사실 한 개 / 질문 하나에 답한다 | O1-1, O1-3 |

## 9. 리스크

| 리스크 | 대응 |
|---|---|
| **작품 집중**(상위 영상이 한 드라마) | 작품별 최근 30일 조회 비중 **50% 초과 시 경고**, 작품 분산 지표 |
| 원작 영상 재사용 수익 구조 | 성과가 커도 권리 문제 해결을 뜻하지 않는다. `rights_status`·업로드 전 권리 확인 유지. 작품 표기 ≠ 허락 |
| "한국 쇼츠 미제공 작품" 같은 목록 | 제공 여부가 공식 클립 허락인지, 아직 다른 채널이 안 만든 작품인지에 따라 의미가 **반대**. 후자면 경쟁은 적어도 권리 위험은 높다 → 확인 전 `unverified` |
| 반복·대량 생산 정책 | 사람 검수·편집 개입 기록 유지(R9-6), AI 음성 공개 의무 확인(A10-10) |
| 구독 전환 낮음(조회 대비 매우 낮은 구독 증가) | 추천 알고리즘 의존. 구독·외부 유입 지표 병행 |
| 성공 사례 편향 | 강의 수치는 목표로 쓰지 않고 우리 첫 10편 값으로 기준을 세운다 |
| 평균 회귀 | 28일뿐 아니라 최근 7일·신규 영상 타율을 별도 감시 |
