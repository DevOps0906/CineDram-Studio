## ADR-001 스택 — 로컬 우선

- **상태:** 채택. 웹 프레임워크는 **FastAPI 확정**(2026-11-02 사용자 승인).
- **맥락:** 엔진은 Python 3.11 표준 라이브러리 + ffmpeg/ffprobe다([docs/00 §8](00-통합설계서.md)). 실행 구조는 웹 서버 1개(8765)와 포트 없는 워커 1개([docs/01 §1](01-상태머신과데이터모델.md), ADR-005). 단계 1은 로컬 SQLite([docs/00 §13](00-통합설계서.md)). 시안은 정적 HTML + `design/wireframes/_app.css`·`_tokens.css`(브라우저가 `@theme`를 못 읽어 만든 `design/tokens.css`의 정적 사본).
- **불일치 정리:** `AGENTS.md` "웹앱 아님"과 [docs/03 반응형 기술 메모](03-화면설계.md) "Next.js + Supabase 가 목표 스택"이 충돌한다. **스택 정본은 이 ADR 한 곳으로 둔다.** 제안 문구: AGENTS.md → "공개 웹앱 아님. 127.0.0.1 로컬 운영 화면 + 스킬·규칙 세트", docs/03 → "스택은 docs/16 ADR-001". 두 파일 수정은 팀장 몫.
- **결정:**

| 층 | 선택 | 비고 |
|---|---|---|
| 언어 | Python 3.12 (실제 개발 환경, 엔진은 3.11 호환 표준 라이브러리만) | 엔진과 같은 런타임 |
| 웹 서버 | FastAPI + ASGI 서버(uvicorn 후보) + Jinja2 서버 렌더 — **확정** | 2026-11-02 고정: fastapi 0.162.0 · starlette 1.10.0 · pydantic 2.14.2 · uvicorn 0.54.0 · Jinja2 3.1.6 · httpx 0.28.1. `requirements.in` → `requirements.txt` `==` 정확 고정 + 해시 고정(`uv pip compile --generate-hashes --python-version 3.11`). 테스트용 httpx는 `requirements-dev.in`(`-c requirements.txt`) → `requirements-dev.txt` |
| UI | 서버 렌더 HTML + `_app.css`·`_tokens.css` 재사용. 클라이언트 JS는 폴링·폼 보조만 | Tailwind 빌드 없이 시작. 토큰 사본 동기화 방식은 확정 대기(열린 질문 6) |
| DB | SQLite (표준 라이브러리 `sqlite3`, ORM 없음) | ADR-004 |
| 미디어 | ffmpeg/ffprobe (엔진이 호출) | 설치 버전 기록 |
| 엔진 | `engine/shortsflow.py` 그대로. **서버 의존성을 엔진에 넣지 않는다** | ADR-005 |

| 웹 서버 후보 | 장점 | 단점 | 판단 |
|---|---|---|---|
| FastAPI + Jinja2 | 라우팅·입력 검증·테스트 클라이언트 내장, 엔드포인트 표가 곧 API 계약(OpenAPI), SSE 전환([docs/01 §6](01-상태머신과데이터모델.md)) 수월 | 새 의존성 여러 개 → 공급망 관리(잠금 파일·`secscan`) | **채택(잠정)** |
| 표준 라이브러리 `http.server` | 의존성 0, 엔진과 같은 원칙 | 라우팅·폼 파싱·템플릿·CSRF를 직접 작성(`cgi` 모듈은 3.11에서 폐기 예고, 3.13 제거) → 보안 코드를 손으로 쓰는 면이 넓다 | 기각: 보안 골격(ADR-003)을 손으로 짜는 위험이 의존성 위험보다 크다 |
| Flask | 단순, 서버 렌더 성숙 | 입력 검증·API 문서 별도, SSE 별도 처리 | 대안으로 유지 |
| Next.js + Supabase | SaaS 전환에 유리 | 로컬 1인 도구에 원격 DB·Node 빌드 체인 추가, 엔진(Python)과 런타임 분리 | 로드맵 단계 6(SaaS) 때 재평가 |

- **결과:** 웹 서버·워커·엔진이 같은 Python으로 돈다. 새 의존성이 생기므로 개발 0단계는 위험도 높음(구현 순서 표).
- **되돌리는 비용:** 서버 층만 바꾸면 된다(중). 서비스 계층·DB·엔진은 프레임워크와 분리해 두면 Flask·표준 라이브러리로 옮길 때 라우팅·템플릿만 다시 쓴다. Next.js 전환은 UI 전체 재작성(큼).

## ADR-002 LLM 호출 주체

- **상태:** 채택(잠정) + **확정 대기**([docs/14 §8-11](14-환경설정과대기큐.md) 사용자 미응답).
- **맥락:** 정본은 "단계 0 Claude 데스크탑 수동 → 단계 1부터 Claude Code 헤드리스 호출, 호출은 작업 단위로 분리"([docs/01 §1](01-상태머신과데이터모델.md)). 그 뒤 환경설정에서 API 키 3종(Claude·ChatGPT·Gemini) 등록이 요청됐다([docs/14 §2 S-ST2](14-환경설정과대기큐.md)).
- **결정:** 1순위 = Claude Code 헤드리스(워커가 서브프로세스로 호출). API 키 3종 직접 호출은 **후순위 확장**(개발 6단계 이후). 공통 조건:

| 조건 | 내용 |
|---|---|
| 호출 단위 | 소재 선정 / 흐름·후킹·제목 / 지시서 / 자막 — 단계별 1호출([docs/01 §1](01-상태머신과데이터모델.md)) |
| 출력 | 정해진 JSON 형식만 받고 서버가 검증. 검증 실패 = 재시도 상한 안에서 재시도 |
| 도구 권한 | 헤드리스 실행은 쓰기·셸 도구 없이(읽기 전용). 정확한 CLI 옵션은 작업 시점 확인 |
| 기록 | `llm_calls`(현재 ❌, [docs/00 §15](00-통합설계서.md))를 개발 6단계에서 함께 만든다 |
| 한도 | 제공자별 일·월·작업당·재시도 상한, 초과 시 `held_resource`([docs/14 §6-4](14-환경설정과대기큐.md), 값 `미확인`) |
| 모델 이름 | 설정값, 코드에 박지 않음([docs/00 §11](00-통합설계서.md)) |

- **대안과 기각 이유:** API 직접 호출로 전환 — 키 저장·비용 한도·제공자별 형식 차이를 처음부터 떠안는다. 사용자 답 전까지 보류.
- **결과:** 우리 프로그램이 Claude 키를 직접 다루지 않는다(헤드리스는 사용자의 Claude Code 로그인을 쓴다). 대신 Claude Code 설치·로그인이 전제가 된다. 자동 호출이 Claude Code 이용 조건에 맞는지 `미확인`(근거 필요).
- **되돌리는 비용:** 작음~중. 호출을 "제공자 어댑터" 한 곳으로 모으면 API 방식 추가는 어댑터 추가로 끝난다.

## ADR-003 로컬 서버 보안 골격

- **상태:** 채택. 규칙 본문은 [docs/14 §5](14-환경설정과대기큐.md)·위협 메모가 정본이고, 여기서는 **구현 순서와 체크리스트**만 둔다.
- **맥락:** 노출 면은 로컬 서버·설정 화면·큐 조작·외부 호출([docs/14 위협 메모](14-환경설정과대기큐.md)). 원격 접속은 정하지 않음([docs/15 §3](15-커리큘럼반영.md)).
- **결정 — 구현 순서(개발 2단계, 화면보다 먼저):**

| 순서 | 항목 | 확인 방법(테스트) |
|---|---|---|
| 1 | `127.0.0.1` 바인딩 고정. 설정으로 `0.0.0.0` 불가. 요청마다 클라이언트 주소가 루프백인지도 검사 | 바인딩 주소 검사, 루프백 아닌 클라이언트 → 거부 |
| 2 | Host 헤더 허용 목록(`127.0.0.1:<포트>`, `localhost:<포트>`) | 다른 Host → 거부 |
| 3 | 상태 변경은 POST만 + Origin 검사, CORS 열지 않음 | 다른 Origin → 거부 |
| 4 | 세션 CSRF 토큰(서버 기동 시 만든 비밀로 서명, 쿠키 SameSite=Strict) | 토큰 없음·불일치 → 거부 |
| 5 | 키·토큰 평문 반환 엔드포인트 금지. 실행 중에도 응답 본문을 검사해 키 패턴이 있으면 차단(스트림·영상·이미지 제외) | 전 라우트 응답에 키 패턴 없음, 키 포함 응답 → 403 |
| 6 | 로그 마스킹, 자식 프로세스 환경 변수 허용 목록 | 로그에 키 패턴 없음 |
| 7 | 파일 경로 입력은 작업 루트·`원본/` 안으로 제한, 서브프로세스는 인자 목록(셸 없음) | 경로 탈출 입력 → 거부 |
| 8 | 비밀은 OS 비밀 저장소 + DB 참조(개발 7단계, 저장소 최종 선택은 [docs/14 §6-5](14-환경설정과대기큐.md) 팀장 결정 필요) | 참조만 저장 |

- **추가 위협 메모(이 문서에서 새로 생긴 면만):**

| 항목 | 내용 |
|---|---|
| 노출 면 | 워커 → 엔진 서브프로세스, 워커 → Claude Code 헤드리스 |
| 입력 | 원본 SRT·제목·사용자 수정 요청 문장(신뢰하지 않는 텍스트) |
| 체인 | SRT 안 지시문 → 헤드리스 LLM이 도구 실행(프롬프트 주입). UI 경로 입력 → 작업 폴더 밖 파일 접근 |
| 결정 | 헤드리스는 읽기 전용 도구, 출력은 JSON 검증 후만 반영, 승인은 사람(P0). 경로 정규화·루트 제한 |
| 로그 | 호출 메타는 남기고 원본 본문·키는 남기지 않음 |
| 로컬 다른 포트 = 같은 사이트 | 쿠키는 포트를 가리지 않아 127.0.0.1·localhost의 다른 포트 앱이 같은 이름 CSRF 쿠키를 남길 수 있고, SameSite=Strict는 다른 포트 요청을 막지 못한다. 대응: Origin은 포트까지 정확 비교, 같은 이름 쿠키가 2개 이상이면 403 + 쿠키 삭제 안내 |

- **잔여 위험(수용, 2026-11-02):** 같은 PC의 로컬 프로세스(헤드리스 Claude Code 포함)는 브라우저가 아니므로 GET으로 CSRF 쿠키·토큰을 받고 Origin을 위조해 승인 POST를 보낼 수 있고, `shortsflow.py approve` CLI·SQLite 직접 쓰기도 가능하다. 코드로는 막지 않고 Claude Code 권한 거부 규칙(`.claude/settings.json`: approve CLI·8765 대상 curl/Invoke-WebRequest·studio.db sqlite3)으로 받친다. 에이전트가 직접 짠 스크립트까지 완전히 막지는 못한다 — 헤드리스 LLM은 읽기 전용 도구만(개발 6).
- **로그인:** 사용자 1명으로 확정(2026-11-02). 로그인 화면은 만들지 않고 위 1~4로 막는다. 여러 명으로 바뀌면 미들웨어 한 층을 더한다.
- **되돌리는 비용:** 작음(미들웨어 한 층). 빼는 쪽은 위험이 커서 되돌리지 않는다.

## ADR-004 DB·마이그레이션

- **상태:** 채택.
- **맥락:** 데이터 모델 제안은 [docs/00 §9](00-통합설계서.md)·[docs/01 §3](01-상태머신과데이터모델.md)·[docs/14 §3](14-환경설정과대기큐.md)에 흩어져 있고 필드명 미확정이다.
- **결정:**

| 항목 | 내용 |
|---|---|
| 방식 | 번호 붙인 SQL 파일(`NNNN_요약.sql`, 위치는 구현 때 정함). `schema_migrations`(버전·적용 시각·체크섬) |
| 불변 | **적용된 파일은 수정 금지.** 체크섬이 다르면 서버 기동 거부. 고칠 때는 새 번호 파일 |
| 설정 | WAL 모드, 외래 키 켬, busy timeout(값은 구현 때) |
| ERD | 손으로 그리지 않는다. 마이그레이션에서 `sql2erd`로 `docs/diagrams/erd.mmd` 생성 → `mmd-check` (구현 작업의 완료 조건) |
| 백업 | 마이그레이션 적용 전 DB 파일 복사 |

| 범위 | 테이블 | 개발 단계 |
|---|---|---|
| **1단계 확정 범위** | `works`, `sources`(origin·rights_status), `jobs`(+ `queue_state`·`priority`·`slot_id`·`hold_reason`), `job_events`, `topics`, `approvals`, `outputs`, `schema_migrations` | 2 |
| 후속 | `ai_providers`, `llm_calls` | 6 |
| 후속 | `accounts`, `settings_events`, `external_sessions`, `radar_*` | 7 |
| 후속 | `google_accounts`, `yt_channels`/`channels`(합칠지 [docs/14 §8-6](14-환경설정과대기큐.md)), `jobs` 업로드 필드 | 8 |
| 후속(로드맵 2·4) | `links`, `capcut_logs`, `tts_clips`, `performance`, `planning_points` 등 | 미정 |

- **`approvals`와 `기획승인.json`:** 엔진 `gate`가 읽는 `기획승인.json`(`plan_hash`)이 정본이고 `approvals`는 조회·감사용 사본으로 제안한다. 불일치하면 파일을 따른다 — 팀장 결정으로 채택(2026-11-02). 채널 바인딩 필드([docs/14 §6-1](14-환경설정과대기큐.md))는 개발 8단계.
- **대안과 기각 이유:** ORM 자동 마이그레이션 — 의존성 추가, SQLite의 열 변경 제약을 감춰 실수를 키운다.
- **되돌리는 비용:** 작음(SQL 파일이라 다른 도구로 옮기기 쉬움). 단계 6 원격 DB 전환 때 SQL 방언 차이 수정 필요.

## ADR-005 작업 실행·큐

- **상태:** 채택. 8766 → 포트 없는 워커, 해시 재검사는 슬롯 집을 때마다(아래 표) — 팀장 결정(2026-11-02).
- **맥락:** 큐 규칙(조건부 UPDATE, 슬롯 분리, 승인 해시 재검사)은 [docs/14 §4](14-환경설정과대기큐.md)·[diagrams/queue-flow.mmd](diagrams/queue-flow.mmd)가 정본. LLM 슬롯 병렬 여부는 사용자 확정 대기([docs/14 §8-1](14-환경설정과대기큐.md)).
- **결정 — 프로세스 모델:** 웹 서버 1개(8765, 화면·조회·사람 조작) + **워커 프로세스 1개**(큐 실행). 둘은 SQLite로만 통신한다. 워커는 듣는 포트가 없다 — [docs/01 §1](01-상태머신과데이터모델.md)의 8766 "제작 서버"를 대체해 노출 면이 하나 준다(팀장 결정 2026-11-02).
- **결정 — SQLite에서 큐 규칙 구현:**

| 규칙 | 구현 |
|---|---|
| 한 작업자만 집기 | `BEGIN IMMEDIATE`(쓰기 잠금) 안에서 슬롯 종류별 `running` 수 확인 → `UPDATE … SET queue_state='running', slot_id=? WHERE id=? AND queue_state='waiting'` → 바뀐 행이 1개일 때만 진행 |
| 슬롯 | GPU·ffmpeg 슬롯 1 고정. LLM 슬롯 수는 설정값(기본값 `미확인`, 사용자 확정 전엔 1) |
| 승인 해시 재검사 | 슬롯을 잡을 때마다 현재 컷표 해시 = 승인 해시인지 확인, 다르면 `held_human`. 최종 방어는 엔진 `gate`(렌더·핸드오프·위임이 이미 호출) |
| 상태 기록 | 상태 전이와 `job_events` 기록을 한 트랜잭션에 |
| 멈춘 작업 | 워커 기동 때 남은 `running` 행을 `waiting`으로 되돌린다(`worker/queue.py` `recover_running`). 임대·heartbeat 필드는 선택 이식 항목(0004) |

- **결정 — 엔진 호출:** **서브프로세스**(`python engine/shortsflow.py <명령> <컷표.json>`, 인자 목록, 시간 제한, 환경 변수 허용 목록, 출력은 작업 로그로). 종료 코드 0 성공 · 1 점검 위반 · 2 실행 오류(엔진 `main` 기준).

| 엔진 호출 후보 | 장점 | 단점 | 판단 |
|---|---|---|---|
| 서브프로세스 | 엔진 변경 0, 장시간 ffmpeg가 죽어도 워커는 산다, 사람이 쓰는 CLI와 같은 경로 | 결과가 출력 문자열·파일 → 파싱 필요 | **채택** |
| 임포트 | 빠름, 구조화된 결과 | 엔진 함수가 출력·파일 쓰기와 섞여 있음, 엔진에 서버 사정이 스며듦 | 기각 |

- **해시 재검사 방법:** 엔진 `gate`를 별도 프로세스 `core/gate_cli.py`(마지막 줄 JSON: ok·plan_hash·reason)로 실행한다. 엔진 변경 없음, 서버·워커는 엔진을 임포트하지 않는다. 워커는 render·handoff·delegate 전에 부르고, 불일치 또는 DB `plan_hash`와 다르면 `held_human`(팀장 결정 2026-11-02).
- **되돌리는 비용:** 중. 워커를 웹 서버 안 스레드로 합치거나 큐 라이브러리로 바꾸려면 실행 계층만 다시 쓴다(DB 스키마 유지).

## ADR-006 테스트·품질

- **상태:** 채택.
- **맥락:** 단위 테스트 ❌([docs/00 §15](00-통합설계서.md)). `tests/` 구조는 tester가 작성 중이므로 **여기서 정하지 않고 `tests/` 결과를 따른다**(실행 명령 포함).
- **결정 — 단계별 완료 조건(테스트로 확인할 것만):**

| 영역 | 완료 조건 |
|---|---|
| 엔진 회귀 | `engine/examples/make_sample.py`로 `check → recalc → render` 통과(AGENTS.md 작업 방식) + `tests/`의 엔진 테스트 |
| P0 게이트 | 승인 없음·승인 뒤 컷표 변경 → 렌더 거부 |
| 마이그레이션 | 빈 DB에서 전체 적용 성공, 적용된 파일 체크섬 변경 → 기동 거부 |
| 큐 | 같은 `waiting` 행을 두 작업자가 동시에 집으면 1개만 성공, GPU 슬롯 동시 점유 1 |
| 보안 골격 | ADR-003 체크리스트 1~7 각각 거부 테스트 |
| 화면 | 3구간(375·768·1280) 스크린샷(`shot`) + codex-reviewer(design·a11y) |
| 공급망 | 잠금 파일 커밋, 커밋 전 `secscan` |

- **결과:** 린터·테스트로 잡히는 것에 리뷰 모델을 쓰지 않는다. AGENTS.md의 "테스트·린터 없음" 문구는 개발 0단계 뒤 갱신 필요(팀장 몫).
- **되돌리는 비용:** 작음.
