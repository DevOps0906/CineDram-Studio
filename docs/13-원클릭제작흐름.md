# 13. 원클릭 제작 흐름 (STEP 1~6 + 인물·작품 레이더)

강의 캡처 9장(중복 1장, 아래 §0)에 보이는 "원클릭 제작" 흐름을 설계에 반영한 문서다. 레이더 모듈 자체는 [docs/12](12-레이더모듈.md), 화면 공통 규칙은 [docs/03](03-화면설계.md)을 따른다.
**캡처의 화면·문구는 전달값이며 검증하지 않았다.** 캡처 속 작은 글씨는 판독값이라 오독 가능성이 있다. 캡처에 없는 수치·기능은 `미확인` 또는 `제안`으로 표시한다.

| 용어 | 뜻 |
|---|---|
| 제작 방식 | 원클릭 폼 ①의 **구성**(한드짜 등, `rules/` 파일, §4) |
| 제작 모드 | 승인된 컷표를 영상으로 만드는 **실행기** 3가지: 자동제작 · 캡컷으로 편집 · Aside 사용하기(§16, `exec_mode`) |

## 3. 레이더 후보도 게이트를 면제받지 않는다

- 레이더 GO·오늘의 픽·높은 점수는 **"무엇을 만들지"의 근거**일 뿐 권리·초상·명예 판단이 아니다([docs/12 §5](12-레이더모듈.md)).
- 흐름은 항상 STEP 6 → 폼 → **권리 게이트(`origin`/`rights_status`) → 기획(구성+컷표) → 기획 승인 P0 → 영상 → 승인함 → 업로드 게이트**.
- 인물 후보는 [`rules/person-fantube.md`](../rules/person-fantube.md) 잠금 규칙(루머·비방 금지)을 함께 적용한다.
- 후보 출처는 `topics.radar_ref`로 남겨 레이더 사용/미사용 타율을 비교한다([docs/12 §3](12-레이더모듈.md)).

## 14. 말로 고치기 = 승인함 [수정 요청]의 입력 방식

근거: [images2/…02_34_21_117](../_원본_무료판/images2/캡처_2026_11_02_02_34_21_117.png) "STEP 5 마음에 안 들면 말로 고치기" — "무엇을 고칠까요?" 자연어 입력칸 + 수정 대상 칩, 문구 "'첫 장면 더 세게' 한마디면 다시 만들어 줍니다". 캡처 속 영상 제목은 옮기지 않는다.

흐름(제안): 자연어 입력 + 칩 → **AI가 컷표·기획 수정안 작성** → 바뀐 곳 비교 표시 → **사람 재승인(`approve`)** → 승인 해시 갱신 → 재렌더. 영상 단계에서 직접 고치지 않는다(P0-3), 승인 뒤 컷표가 바뀌면 재승인(P0-2, 엔진 `gate`가 이미 거부함).

| 칩(캡처) | 고치는 곳 | §10 자동 검수 항목 |
|---|---|---|
| 자막 싱크 | 자막 재계산(`recalc`) | 자막 싱크 |
| 제목 | 기획(관문 ②) | — |
| 후킹 첫 장면 | 기획(후킹 시각·대사, 컷표 컷 1) | — |
| 결말 잘림 | 컷표 마지막 컷 경계 | 말끝 보존 |
| 소리 크기 | 렌더 음량 설정 | 음량 |
| 브금 | 렌더 오디오 설정(현재 엔진에 브금 없음) | — |
| 효과음 | 렌더 오디오 설정(현재 엔진에 효과음 없음) | — |
| 그 뒤 2개(보조자막 등으로 보이나 잘림) | `미확인` | — |

- 구현: ❌ 자연어 수정 요청·칩·수정안 생성 코드 없음. 있는 것은 승인 뒤 컷표 변경을 막는 `gate`(P0-2)뿐.
- [docs/01](01-상태머신과데이터모델.md) 상태도는 `review → building: 수정 요청`으로 바로 이어진다. 재승인 단계를 거치는 위 흐름과 맞는지 확인 필요(§15).

## 16. 제작 모드 3가지 (사용자 분류, 2026-11-02)

사용자 지시: "제작모드는 자동제작, 캡컷으로 편집, Aside 사용하기 이렇게 3가지 버전으로 분류". 기존 제작 형태 A/B/C([docs/06](06-제작형태와TTS.md), [docs/08 §1](08-보관함과성과와타율.md))와 1:1로 대응한다. 각 모드의 상세 내용은 그 문서가 정본이다.

| 제작 모드 | 형태 · `exec_mode` · 명령 | 담당 | 사람 개입 지점 | 권장 상황(docs/06·08) | 구현 |
|---|---|---|---|---|---|
| 자동제작 | A · `auto_render` · `render` | 엔진 | 완성본 확인·승인 | 편수 증가, 재현성 | ✅ 합성 샘플만 검증 |
| 캡컷으로 편집 | B · `manual` · `handoff` | 사람 + 캡컷 | 캡컷 편집 전체, 시각 오차 기록 | 처음 몇 편(정답 기준) 권장 | ✅ 합성 샘플만 검증 |
| Aside 사용하기 | C · `ai_assistant` · `delegate` | 외부 AI 어시스턴트 | 결과 전체 검수(매번 달라 필수) | 빠른 초안 + 사람 검수 | ⚠ 패키지 생성만, 외부 결과 검증 안 함 |

- 입력은 세 모드 모두 **승인된 `컷표.json`**(+ 자막·TTS)이고, 산출물은 docs/06의 형태별 설명(완성 mp4 / `캡컷패키지/` / `위임패키지/`)을 따른다.
- **Aside = 별도 외부 AI 도구(AI 브라우저 앱), 제작 모드 C(`delegate`)에 대응** — 2026-11-02 사용자 확정, 정의는 [docs/08 §1](08-보관함과성과와타율.md). 연동 방식은 미확인(§15-16). Aside 로그인 상태는 환경설정 계정 탭에서 보고, 제작 모드 Aside인데 미로그인이면 폼에 경고 + 환경설정 링크([docs/14 §2](14-환경설정과대기큐.md)).
