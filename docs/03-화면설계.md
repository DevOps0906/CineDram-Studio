# 03. 화면 설계 (3구간 반응형)

단계 1(만들기 화면)과 단계 3(제작 현황·승인함)의 기준. 모바일의 핵심은 **승인 대기 카드를 한 손으로 처리**하는 화면이다.

## 구간

| 구간 | 폭 | 레이아웃 |
|---|---|---|
| 모바일 | ~767 | 1열. 하단 탭(홈 · 제작 현황 · 승인함). 승인 카드 중심 |
| 태블릿 | 768~1199 | 2열. 메뉴 접기형 + 중앙. 제작 현황은 우측 드로어 |
| 데스크톱 | 1200~ | 3열. 좌측 메뉴 / 중앙 작업 영역 / 우측 제작 현황 |

## 폰트 토큰

| 요소 | 모바일 | 태블릿 | 데스크톱 |
|---|---|---|---|
| 본문 | 14px | 15px | 16px |
| 카드 제목 | 16px | 18px | 20px |
| 페이지 제목 | 22px | 26px | 32px |
| 표·라벨 | 12px | 13px | 14px |

- 터치 타깃(영상 확인·승인·수정 요청·다시 만들기): **최소 높이 44px**.
- 스택 전제: Tailwind CSS v4 `@theme` 토큰으로 구간별 폰트 지정, 작업 시점의 최신 stable 확인 후 버전 기록.

## 화면 목록

| 화면 | 단계 | 내용 |
|---|---|---|
| 만들기 | 1 | 작품/원본 선택 → 구성 → 소재 모드 → 속도 → 실행. 클릭 3번 목표 |
| 관문 ① 소재 | 1 | 후보 3개 카드(점수·킥·끝 장면) → 선택 |
| 관문 ② 제목 | 1 | 흐름 4줄, 후킹 2, 제목 3 → 선택/수정 |
| 제작 현황 | 3 | 진행 중 / 승인 대기 목록, 5단계 진행바 |
| 승인함 | 3 | 카드: 영상 확인 · 승인 · 수정 요청 · 다시 만들기 · 취소 |
| 링크로 만들기 | 2 | URL → 확인 → 작품 매칭 → 원본/자막 → 소재 지정 |
| 레이더 | 5 | 진입 성적표, 데일리 떡상쇼츠, 황금키워드, 결 지도 |
| 원클릭 제작 | 1 (레이더 연동 5) | 제작 방식(규칙 파일) → 소재(비우면 레이더 후보 제시) → 제작 모드(자동제작·캡컷으로 편집·Aside, [docs/13 §16](13-원클릭제작흐름.md)) → 채널 업로드 방식 요약(읽기 전용, 환경설정에서 선택) → 실행. 상세 [docs/13](13-원클릭제작흐름.md) |
| 환경설정 | 1~3 (업로드 6) | 탭 3개: 계정 설정 · AI API 설정 · 업로드 방식. 상세 [docs/14](14-환경설정과대기큐.md) |
| 리스크 기록 (S-RK1) | 3 | 채널별 경고·스트라이크 수동 기록, 작품 안전 등급. 업로드 전 점검은 승인함에 둔다. [docs/15 §2](15-커리큘럼반영.md) |
| 홈 "오늘 할 일" 섹션 | 3 | 소재 고르기 · 기획 승인 · 업로드 승인 대기 수 → 각 게이트. [docs/15 §2](15-커리큘럼반영.md) |
| 채널 관리 (S-CH1) | 6 | 사이드바 독립 메뉴. 좌측 구글 계정 목록 + [＋ 구글 계정 추가] + 우측 선택 계정 상세(채널 등록·해제·제거). 상세 [docs/14 §2](14-환경설정과대기큐.md) |

- 커리큘럼 반영 결과 기존 화면에 흡수한 것: 원클릭 쇼츠/롱폼/기타 탭·규칙 [내보내기]·[가져오기], AI API 탭 사용량·한도, 채널 성적표 규칙 후보, 레이더 황금키워드 탭. 최종 사이드바는 [docs/15 §2-1](15-커리큘럼반영.md).
| 대기 큐 | 1~3 | 동시 제작 슬롯, 순서 변경·일시정지·재개·취소·재시도. 사람 게이트 대기는 슬롯 비점유. 상세 [docs/14 §4](14-환경설정과대기큐.md) |

- 레이더 카드의 [원클릭으로 만들기] → 원클릭 제작 폼에 소재를 채워 넘긴다. 권리 게이트·기획 승인은 그대로 거친다([docs/13 §3](13-원클릭제작흐름.md)).

## 제작 현황 패널

| 요소 | 내용 |
|---|---|
| 갱신 | 단계 3은 3초 폴링 → 이후 SSE |
| 묶음 | 진행 중(n) / 승인 대기(n) |
| 카드 | 작품명 + 구성 배지 + 경과 시간 |
| 진행바 | 소재 → 원본 → 제작 → 검수 → 업로드 |
| 로그 | "소재 선정 · 완료 · 11분 7초", 렌더 횟수, 자세히 펼치기 |
| 상태 배지 | 제작 가능 / 업로드 검토 필요 / 원본 없음 / **권리 미확인** / 디스크 부족 |

- 원클릭 내부 6단계와 진행바의 대응: 받아쓰기=원본, 대본·제목=소재, 장면 맞추기·목소리·자막=제작, 자동 검수·렌더=검수. 기획 승인 대기는 제작 칸에서 멈춤으로 표시([docs/13 §9](13-원클릭제작흐름.md)).

## 승인함 카드 (모바일 기준)

```
┌────────────────────────────┐
│ [한드짜] 작품 · E07   49분  │
│ 제목 두 줄                  │
│ ▶ 영상 확인                 │
│ 점검 ✓14 △2 ✗0   ⚠경계 3    │
│ ☐1 ☐2 ☐3 ☐4 ☐5 ☐6  (캡컷)  │
│ [승인] [수정 요청] [다시 만들기] │
└────────────────────────────┘
```

- `권리 미확인` 카드는 **[승인]** 대신 **[보관]** 만 노출한다. 업로드 경로가 열리지 않는다(R9-1).
- 업로드 예약 버튼은 `rights_status ∈ {own, licensed}` 이고 사람이 [승인] 한 카드에서만 활성화한다.
- 승인 로그(누가, 언제, 어떤 점검 결과로)를 보관한다.
- [수정 요청]은 자연어 입력 + 수정 대상 칩으로 받고, AI 수정안 → 사람 재승인 → 재렌더로 이어진다([docs/13 §14](13-원클릭제작흐름.md)).

## 링크로 만들기 (단계 2)

링크 확인 → 작품 매칭 → 원본 보유 확인 → 자막 보유 확인 → 소재 지정 → 제작 시작 또는 "원본 들어오면 자동 제작" 대기.
"+ 구성 추가"는 **링크 1개 → 작업 N개**(jobs 1:N). 같은 링크라도 소재 모드(같은 결 다른 소재 / 같은 결 같은 소재 · 다른 번역본)에 따라 서로 다른 영상 N개가 나온다([docs/13 §12](13-원클릭제작흐름.md)). 링크의 쇼츠는 분석용이며 소스로 쓰지 않는다(R9-2). 매칭 신뢰도 낮음이면 모달에서 작품명 수정을 요구한다.

## 반응형 기술 메모

- 구성 7종의 규칙 파일은 서버가 읽어 UI에 **배지와 규칙 요약**으로 노출한다(구성 추가 = 규칙 파일 추가, UI 코드 변경 없음).
- Next.js + Supabase 가 목표 스택. 단계 1은 로컬 SQLite 로 충분.
