# 쇼츠 설계도

영상 한 편(또는 한 회차)에서 **시청자가 끝까지 보는 쇼츠 한 편**을 설계한다.
편집은 사람이 캡컷에서 하고, 이 스킬은 "어디를, 어떤 순서로, 무슨 말을 붙여 자를지"를 원본 시각까지 정해 준다.
영상은 만들지 않는다(미리보기 제외).

폴더 위치는 이 파일 기준으로 `../../rules/`, `../../modes/`, `../../docs/`.
**판단 기준은 규칙 파일에 있다. 단계에 들어가기 전에 해당 절을 연다.** 규칙은 ID(`C3-2` 등)로 인용한다.

## 0. 시작 전 확인

### 0-1. 입력 받기
1. **원본 영상 경로**와 같은 이름의 **자막(SRT)**. 여러 회차면 회차마다 자막을 받는다.
2. 자막이 없으면 「0-3. 자막 만들기」. **자막 없이 대사 시각을 짐작해서 진행하지 않는다**(P8-1).
3. 결과는 원본 옆 `쇼츠_<작품>_<회차>` 폴더에 저장한다.

### 0-2. 권리 게이트 (R9-1 🔒) — 가장 먼저
사용자에게 소스의 출처와 권리를 **한 번에** 묻는다. 모르면 `unverified`.

| origin | 설명 |
|---|---|
| `local_file` | PC에 있는 파일 |
| `own_youtube` | 본인 채널 영상(스튜디오에서 내려받음) |
| `licensed` | 라이선스·공식 클립 제공 |
| `external_youtube` | 남의 유튜브 영상 |

| rights_status | 처리 |
|---|---|
| `own` / `licensed` | 진행 |
| `unverified` | **지시서·자막·미리보기까지만.** 업로드 예약 안내 금지. 지시서 머리에 `권리 미확인` 표기 |

- 남의 쇼츠 **링크**를 받으면 구성·제목 패턴·장면 유형만 분석한다. 그 편집본을 소스로 쓰지 않는다(R9-2).
- 저작권을 단정하지 않는다. 물으면 R9-3 문구로 답한다.

### 0-3. 구성과 소재 모드 고르기
1. **구성**(규칙 파일)을 고르게 한다. 기본은 소스에 맞춰 추천하고 이유를 한 줄 적는다.

| 구성 | 규칙 파일 | 맞는 소스 |
|---|---|---|
| 한드짜(갈등·반전) | `rules/drama.md` | 드라마·영화 |
| 1인칭 한드짜 | `rules/drama-first-person.md` | 드라마·영화(당하는 주인공 시점) |
| 감동 반전형 | `rules/touching-reversal.md` | 드라마·영화 |
| 1인칭 나레이션형 | `rules/first-person.md` | 주인공 시점이 뚜렷한 소스 |
| 예능형 | `rules/variety.md` | 예능 |
| 자체 보유 콘텐츠 | `rules/own-content.md` | 본인 다큐·강의·직접 촬영 |
| 인물·팬튜브·1분 카테고리형(초안) | `rules/person-fantube.md` | 레이더 후보(실존 인물·스포츠 클립). 권리·루머 규칙 강함 |
| 인드짜형 | `rules/indie.md` | **정의 전.** 고르면 공통 규칙만 쓰고 사용자에게 알린다 |

2. **항상 `rules/common.md` 를 먼저 읽고**, 고른 구성 파일을 읽는다(조합 구성은 파일에 적힌 대로 모두 로드).
3. **소재 모드**: `modes/topic-modes.md`. 기본은 `새 소재`. 제작 기록(`data/`)이 있으면 같은 소재 / 같은 결 다른 소재 / 같은 결 같은 소재 · 다른 번역본(en/ja 원본을 AI가 한국어로 재번역·의역, 원본이 en/ja일 때만) / 다른 결을 제안한다.
4. 속도 옵션: **검수 후 승인(기본)** / 패스트(관문 ①② 생략 — 사용자가 명시했을 때만). 패스트여도 권리 게이트와 자가 점검은 생략하지 않는다.

### 0-4. 자막 만들기 (SRT가 없을 때)
사용자에게 두 방법을 보여 주고 고르게 한다.

**A. 캡컷·브루 등 편집 프로그램의 자동 자막 (설치 없음)**
- 원본을 넣고 자동 자막을 돌린 뒤 **SRT로 내보내** 원본 옆에 저장해 달라고 안내한다. 메뉴 이름은 버전마다 다르니 '자막 내보내기 / SRT'를 찾으라고만 말한다.

**B. 이 PC에서 직접 받아쓰기 (클로드가 실행)**
1. `python --version` 확인. 없으면 설치 안내 후 멈춘다.
2. `pip install faster-whisper`.
3. 아래 `받아쓰기.py` 를 만들어 실행한다. NVIDIA GPU가 있으면 `cuda`/`medium`, 없으면 `cpu`/`small` 로 바꾸고 "1시간짜리면 30분 넘게 걸릴 수 있어요"라고 먼저 알린다.

```python
import sys
from faster_whisper import WhisperModel
src, out = sys.argv[1], sys.argv[2]
m = WhisperModel("medium", device="cuda", compute_type="float16")  # CPU면: WhisperModel("small", device="cpu", compute_type="int8")
segs, _ = m.transcribe(src, language="ko", vad_filter=True)
def t(s):
    h, r = divmod(s, 3600); mi, se = divmod(r, 60)
    return f"{int(h):02d}:{int(mi):02d}:{int(se):02d},{int(round((se % 1) * 1000)):03d}"
with open(out, "w", encoding="utf-8") as f:
    for i, s in enumerate(segs, 1):
        f.write(f"{i}\n{t(s.start)} --> {t(s.end)}\n{s.text.strip()}\n\n")
        print(i, t(s.start), s.text.strip(), flush=True)
```
실행: `python 받아쓰기.py "<원본>" "<원본과 같은 이름>.srt"`

4. 받아쓰기는 인명·고유명사가 틀린다. 교정하고 `corrections` 에 기록한다(P8-5). 이 SRT는 **자동 받아쓰기**이므로 지시서에 P8-2 문구를 넣는다.
5. 디스크 여유를 확인한다(`docs/01` blocked_disk). 여유가 원본 크기의 2배 미만이면 사용자에게 알리고 멈춘다.

## 1. 줄거리 파악 (common §1)

- 자막을 **처음부터 끝까지 읽는다.** 길면 나눠 읽되 건너뛰지 않는다(C1-3). 호출을 나눌 때도 각 호출이 담당 범위를 처음부터 끝까지 읽는다.
- 짧게 정리해 보여 준다.
  - 인물 관계: 이름 대신 **역할**로(자체 보유 콘텐츠는 실존 인물·사건)
  - 이 원본의 긴장 목록: 누가 누구에게 무엇을 했나(또는 무엇이 궁금한가), 원본 시각과 함께
  - 결 태그 후보(`modes/topic-modes.md`)와 **갈등 유형**(누명·오해 / 들킬 위기 / 선택의 기로 / 그 외, common §1)
  - 작품 매력 태그 **신작 / 명작 / 스타**(작품 선정 참고, 소재 점수와 별개)
  - 갈등 구조를 AI로 먼저 분석했다면, 그 결과는 자막을 끝까지 읽고 사람이 확인한 뒤에만 쓴다(원작 사실을 지어내지 않는다, R9-5)
  - **민감 장면 구간 목록**(19금·목조르기·칼 찌름·마약/약물 투여 등, common §11): 원본 시각과 유형. 없으면 "없음". 자막만으로 판단이 안 서면(화면 묘사가 없는 구간) 그 구간을 사용자에게 "화면 확인 필요"로 넘긴다. 짐작으로 없다고 하지 않는다.

## 2. 소재 후보 3개 → **관문 ①** (common §1 점수표)

후보마다 표 한 줄을 채운다. 점수 70 미만은 넣지 않는다(3개를 못 채우면 2개만 내고 이유를 말한다).

| 칸 | 쓰는 법 |
|---|---|
| 한 줄 요약 | 누가 무엇을 당하고(또는 무엇이 궁금하고) 어떻게 뒤집히나 |
| 원본 구간 | 시작~끝 시각(회차 섞기면 회차별) |
| 기·승·전·결 킥 | 단계마다 킥 하나, 원본 시각과 대사 |
| 끝 장면 | 마지막 대사·마지막 얼굴 |
| 방식 | 한 회차형 / 회차 섞기형 + 이유 한 줄 |
| 결 태그 | 주 1 / 보조 ≤1 |
| 점수 | 항목별 점수와 합계 (구조 품질이며 조회수 예측이 아님) |
| 민감 구간 | 후보 구간이 지나는 민감 장면과 처리 방식(삭제/우회), 처리 뒤에도 킥이 남는지(S11-4) |
| 약점 | 약한 이유가 있으면 솔직히 한 줄 |

→ **사용자에게 고르게 한다.** "알아서 해"면 점수와 끝 장면이 가장 센 후보를 고르고 이유를 적는다.

## 3. 흐름 4줄 · 후킹 · 제목 → **관문 ②** (common §2·§3·§4 + 구성 규칙)

1. **흐름 4줄**(원본 시각 포함): ① 시작 ② 세지는 근거 ③ 대응·결과 ④ 결과 뒤 반응.
2. **후킹 시작점 2개**: 원본 시각 + 첫 대사 + 왜 궁금해지는지 한 줄(C3-7).
3. **제목 후보 3개**: 두 줄, 결과는 숨기고 상황은 보이게. 각 제목 옆에 "이 제목이면 끝 장면은 OO" 를 적는다(C4-2).

→ **사용자에게 고르거나 고치게 한다.**

## 3-1. 기획 확정 → 승인 (common §0-2, 영상보다 먼저)

관문 ①②를 통과하면 **영상을 만들기 전에 기획을 `컷표.json` 의 `meta.plan` 으로 기록**한다: `topic`(소재 한 줄), `conflict_type`(갈등 유형), `appeal`(신작/명작/스타), `flow`(4줄), `hook{time,line}`, `ending`(끝 장면), 제목 두 줄, `rights_status`, `sensitive_review`(민감 장면 없음 | 처리 내용). 컷표를 채우고 `check` 를 통과시킨 뒤, **사용자에게 기획서를 보여 주고 사용자가 `approve` 를 실행(또는 승인 의사 표시 후 실행)** 한다. 승인 없이 렌더·핸드오프·위임 단계로 가지 않고, 승인 뒤 컷표를 고치면 재승인을 받는다. 영상 단계에서 소재·컷·문장을 새로 정하지 않는다(P0-3). 스킬은 사용자 대신 승인하지 않는다.

## 4. 편집 지시서 (common §5·§8)

`편집지시서.md` 머리에 메타를 적고 컷 표를 쓴다. 시각은 **자막 시각 기준 소수 첫째 자리**(P8-1).

```
# 편집 지시서 — <작품> <회차> / <제목 두 줄>
- 구성: <규칙 파일>  / 소재 모드: <모드>  / 결 태그: <주·보조>
- 소스: origin=<…>  rights_status=<…>   (unverified면 "권리 미확인" 굵게)
- SRT: <수동 제공 | 자동 받아쓰기 — 컷 경계 ±0.5초 확인 필요>
- 총 길이: <초>  컷 수: <n>  나레이션 비중: <%>
```

| 번호 | 원본 시작 | 원본 끝 | 길이 | 들리는 것 | 화면 메모 | 소리 메모 | 확인 |
|---|---|---|---|---|---|---|---|
| 1 | 12:03.4 | 12:05.1 | 1.7 | (원음) "지금 뭐라고 했어?" | 말하는 사람 얼굴 크게 (얼굴 우측) | — | |
| 2 | 12:05.1 | 12:08.0 | 2.9 | [나레이션 1] | 듣는 사람 표정 (얼굴 중앙) | | ⚠ 경계 |

- 컷 1은 고른 후킹. 컷 2는 바로 나레이션(C3-4).
- 나레이션 컷 길이는 `글자 수 ÷ 7` 초. 그 길이만큼 **대사 없는 원본 화면**을 깐다(C5-6).
- 대사 컷의 열기·닫기는 P8-3·P8-4 를 따르고, 애매한 경계는 `확인` 칸에 `⚠ 경계`.
- 표 아래: **컷 길이 합 = 총 길이 검산**(C7-3), **끝 3초에 보이고 들리는 것**.
- **`민감 처리` 표**(common §11 양식)를 컷 표 아래에 붙인다. 없으면 "민감 장면 없음". 규칙:
  - **삭제**: 컷 표에서 그 구간을 아예 빼고 문장 경계에서 잇는다(S11-5). 줄어든 시간은 길이 합·자막 재계산에 반영.
  - **우회**: 컷 하나로 두되 `화면 메모`에 `우회: 화면=<대체 원본 시각>`을 적는다. **음성 구간(원본 시작·끝)은 그대로**, 대체 화면 길이 = 음성 길이(S11-6). 대체 화면에는 말하는 입이 안 보이게(S11-7).
  - 민감한 소리는 `소리 메모`에 처리법(삭제/음량 -dB/삐)과 0.1~0.2초 페이드를 적는다(S11-8, S11-9).
  - 후킹 0~2초·끝 3초에 민감 장면이 걸리면 후킹 시작점·끝을 다시 고른다(S11-3).
- 자체 보유 콘텐츠는 `사실 표`(연도·인명·수치와 근거 시각)를 표 아래에 붙인다(O2-1).

`나레이션.txt`: 컷 번호와 같은 번호로 문장을 적고, 문장마다 글자 수와 권장 길이를 괄호로 단다.

## 5. 자막 파일 (common §5 재계산 공식)

`자막.srt` 를 **편집 뒤 타임라인 기준**으로 새로 만든다. 캡컷에 그대로 불러오면 된다.
공식과 C5-9~C5-13 을 따른다. 생성 뒤 줄 번호 연속·겹침 없음·UTF-8·마지막 줄 끝 시각 ≤ 총 길이를 직접 확인한다.

## 6. 미리보기 영상 (선택, ffmpeg 가 있을 때)

`ffmpeg -version` 으로 확인. 없으면 건너뛰고 "ffmpeg를 깔면 미리보기도 만들어 드려요"라고만 적는다.
디스크 여유를 먼저 확인한다(`docs/01` blocked_disk).

1. 컷마다 `cuts/01.mp4` … 로 저장:
   `ffmpeg -y -ss <시작초> -to <끝초> -i "<원본>" -c:v libx264 -crf 20 -preset veryfast -c:a aac "cuts/01.mp4"`
2. `cuts/list.txt` 에 `file '01.mp4'` 순서대로 적고:
   `ffmpeg -y -f concat -safe 0 -i cuts/list.txt -c copy "미리보기.mp4"`
- **우회 컷**은 화면과 음성을 서로 다른 구간에서 가져와 합친다(길이가 같아야 한다):
  `ffmpeg -y -ss <대체화면시작> -to <대체화면끝> -i "<원본>" -ss <음성시작> -to <음성끝> -i "<원본>" -map 0:v:0 -map 1:a:0 -c:v libx264 -crf 20 -preset veryfast -c:a aac "cuts/NN.mp4"`
  - 삭제 컷은 `cuts/` 에 만들지 않는다. 민감한 소리의 음량·삐는 미리보기에 반영하지 않으며 캡컷에서 처리한다(체크리스트 3-1).
- 나레이션 컷은 소리가 비어 있다. 정상이다(TTS는 캡컷에서).
- 재인코딩 오차가 있는 **참고용**이다(P8-6). 세로 변환·얼굴 확대·제목은 캡컷에서 한다.

## 6-1. 컷표.json · TTS · 제작 방식 선택 (엔진: `engine/shortsflow.py`, 설명: `docs/06`, `docs/08`)

1. **컷표.json 작성** — 지시서의 컷 표를 기계가 읽는 형태로 쓴다(샘플: `engine/examples/make_sample.py` 가 만드는 컷표.json). 컷마다 `kind`(dialog/narration), 시각(초 또는 `mm:ss.s`), 나레이션은 `beat`·`label`·`tts_text`·`sub_lines`(자막/TTS 분리, A10-1), 우회는 `visual_start`+`sensitive`, 얼굴 중앙 크롭은 `face{x,y,h}`(원본 대비 0~1, 수동 입력).
2. `python engine/shortsflow.py check 컷표.json` — 규칙 위반을 먼저 고친다.
3. `tts-plan` → `tts/TTS_줄.txt` 를 TTS 도구에 넣어 `NN_이름.mp3` 로 저장(비트당 한 파일, A10-2). 텍스트 확정 전 생성하지 않는다(A10-3).
4. `tts-measure` → 실측 길이. `recalc` → 컷 길이(=실측+0.2초)·타임라인·`자막.srt` 재계산(A10-5, A10-6).
5. `approve 컷표.json --by <이름>` — 기획 승인(사람). 이후에만 아래 제작 명령이 동작한다.
6. **제작 방식을 사용자에게 고르게 한다**(`exec_mode`):
   - `render`(자동화) — 템플릿(`--template topbottom|hookingtime`) 완성 mp4. 사람은 확인·승인만.
   - `handoff`(캡컷 넘기기) — 컷별 파일·음성·자막·체크리스트.
   - `delegate`(AI 어시스턴트 위임) — 프롬프트+파일. 결과는 사람이 검수하고 `방식비교기록.json` 입력.
   처음 몇 편은 `handoff`(정답 기준 확보)를 권한다. 어느 방식도 **업로드하지 않는다**.
7. 채널 스타일을 쓰면 `rules/channel-hookingtime.md` 를 추가로 읽고 켠 옵션을 작업기록에 적는다.

## 8. 자가 점검 (common §12 + 구성 추가 항목)

`common.md` §12 표와 구성 파일의 **추가 점검 항목**을 항목마다 ✓ / △ / ✗ + 이유 한 줄로 채워 `편집지시서.md` 맨 아래에 붙인다.
✗ 는 고친 뒤 다시 점검한다. 고칠 수 없으면 사용자에게 이유를 말한다.

## 9. 마무리 보고

1. 고른 소재·제목 한 줄
2. 만든 파일 목록(경로)
3. 총 길이, 컷 수, 점검 결과(✓/△/✗ 개수)
4. 캡컷에서 할 일 3가지: 세로 맞추기·얼굴 확대 / 나레이션 TTS 입히기 / 제목 넣기
5. `확인 필요 경계` 가 있으면 몇 개이고 어느 컷인지
6. `unverified` 면 한 줄: "권리 미확인 — 업로드 전에 권리를 확인하세요."

## 하지 않는 것

- 원작에 없는 결말·사과·처벌·사실을 지어내지 않는다(R9-5).
- 업로드·채널 운영·수익에 대한 약속을 하지 않는다(R9-4).
- 저작권을 단정하지 않는다(R9-3).
- 사람 확인 없는 자동 업로드를 제안하지 않는다. 기본은 영상까지만, 업로드는 항상 사람이 승인한다.
- 남의 편집본을 소스로 재사용하지 않는다(R9-2).
- 기획 승인(P0-2) 없이 영상을 만들거나, 사용자 대신 기획을 승인하지 않는다.
- 민감 장면(19금·목조르기·칼 찌름·약물 투여 등)을 처리 없이 지시서에 넣지 않는다(S11-1). 처리했다고 플랫폼 정책 통과를 약속하지 않는다.
