# 소재 모드 (topic-modes.md)

한 소재를 여러 갈래로 확장하는 방법. **구성(rules/) × 소재 모드**가 조합된다.
스킬은 2단계(소재 후보) 직전에 이 파일을 연다. 제작 기록(`data/topics`)이 없으면 모드는 `새 소재` 만 쓴다.

## 모드 4종

| 모드 | 하는 일 | 필요한 데이터 |
|---|---|---|
| **같은 소재** | 이미 만든 구간을 **다른 후킹·다른 제목·다른 컷 구성**으로 재제작 | 기존 topics 행(구간·후킹·제목) |
| **같은 결 다른 소재** | 결 태그가 같은 **다른 장면**을 찾는다(같은 영상·링크 1개에서도 장면마다 다른 영상) | topics의 결 태그, 원본 자막 |
| **같은 결 같은 소재 · 다른 번역본** (신규) | 원본 대사가 영어·일본어일 때 **AI가 한국어로 재번역(의역 허용)** 해 나레이션·자막 문장을 새로 쓴다(사용자 확정: "AI 재번역, 영어·일본어 → 의역 가능하도록") | 기존 topics 행 + en/ja 원본 자막(SRT) 또는 받아쓰기 결과 + 언어 코드(`en`, `ja`) |
| **다른 결** | 결 태그가 **다른** 소재를 추천 | topics의 결 태그 분포 |

## 결 태그 (갈등·감정의 종류)

소재마다 **주 결 1개 + 보조 결 최대 1개**를 붙인다. 목록에 없으면 사용자 확인 후 추가한다.

| 결 | 뜻 | 주로 쓰는 구성 |
|---|---|---|
| 무시→통쾌 | 낮게 보던 상대가 실력·정체로 뒤집힘 | drama |
| 정체공개 | 숨긴 신분·관계가 드러남 | drama, drama-first-person |
| 갑질→응징 | 권력 남용이 제3자·증거로 응징됨 | drama |
| 오해→해소 | 오해가 풀리며 감정이 바뀜 | touching-reversal |
| 숨은선의 | 숨긴 배려가 밝혀짐 | touching-reversal |
| 상황웃음 | 상황 어긋남에서 웃음 | variety |
| 말실수웃음 | 말실수·받아치기 웃음 | variety |
| 누명·오해 | 억울한 사람이 풀어내는 과정 | touching-reversal, drama |
| 들킬 위기 | 숨긴 비밀이 들키기 직전의 긴장 | drama, drama-first-person |
| 선택의 기로 | 둘 중 하나만 골라야 하는 딜레마 | drama, touching-reversal |
| 질문→사실 | 의문에 대한 새 사실 | own-content |
| 인과반전 | 알려진 원인이 사실은 달랐음 | own-content |

## 모드별 절차

### 같은 소재
1. `topics` 에서 같은 작품·회차의 기존 행을 모두 읽는다.
2. 새 제작이 아래 중 **둘 이상**을 바꾸지 못하면 만들지 않는다.
   - 후킹 시작점 / 제목 초점 / 컷 구성(주인공 시점·사용 구간) / 구성(rules)
3. **원본 구간 겹침 40% 이하**(길이 기준)로 한다. 40%를 넘으면 사용자에게 "비슷한 영상이 쌓입니다"라고 알리고 선택하게 한다.

### 같은 결 다른 소재
1. 기준 소재의 주 결 태그를 가져온다.
2. 같은 작품의 **다른 회차·다른 구간**에서 해당 결의 후보를 찾는다(소재 점수표 적용).
3. 기준 소재와 **원본 구간이 겹치지 않아야** 한다.

### 같은 결 같은 소재 · 다른 번역본 (AI 재번역)
- 지원 언어: `en`, `ja` 2개만. 그 밖의 언어는 미지원(확정 대기). 한국어 원본에는 쓰지 않는다.
- 채택 안 함: 외부 번역 자막 파일 입히기, 다국어(한국어 외) 버전 제작.

1. 기존 topics 행과 en/ja 원본 자막(SRT 또는 받아쓰기 결과)을 읽는다.
2. AI가 한국어로 재번역·의역해 나레이션·자막 문장을 새로 쓴다. 의역 범위(제안, **사용자 확정 대기**):

| 허용 | 불허 |
|---|---|
| 문장 구조·어순·표현 재구성 | 사실·인물 관계·인과·결말 바꾸기(C5-1, R9-5) |
| 한국어 구어체·호흡 단위로 의역 | 원문에 없는 대사 창작 |
| 채널 톤 반영 | 고유명사 임의 변경 |

3. 원문 대사와 의역을 쌍으로 기록한다: 컷표 `meta.plan.translation[]` = `{cut, lang, source_text, ko_text}`(필드명 제안). 검수 가능하게 남긴다.
4. 기획 승인(P0) 안에 **번역 사실 확인** 지점을 둔다: 의역 전/후 "누가 · 무엇을 · 결말"이 같은지 사람이 확인한다.

중복 규칙과의 관계(제안, **사용자 확정 대기** — 아래 규칙을 완화하지 않는다):
1. 같은 구간을 다시 쓰므로 `같은 소재` 절차 2·3(둘 이상 변경, 구간 겹침 40% 이하)과 C1-8·M-1에 그대로 걸린다. 번역·의역 문장만 바꾼 것은 "둘 이상 변경"으로 치지 않는다.
2. 같은 채널 연속 예약은 R9-6(거의 같은 영상 연속 제작 금지)·M-2에 걸린다 → 같은 채널 연속 예약 금지. **채널이 다르면** 예외로 둘지는 확정 대기.
3. 권리: 의역 번역본은 원본의 2차 가공이다. `rights_status`는 원본 것을 물려받고, 번역으로 새 권리가 생기지 않는다.

### 다른 결
1. 이 작품·채널에서 자주 쓴 결 상위 2개를 피한다.
2. 안 쓴 결을 후보로 3개 낸다. 후보마다 "이 결을 처음 시도하는 이유/위험"을 한 줄 적는다.

## 중복 방지 규칙 (C1-8 의 상세)

- **M-1** 후킹 대사가 기존 topics 의 후킹과 같으면 제외한다.
- **M-2** 같은 채널에서 **같은 날 같은 작품** 쇼츠는 3편을 넘기지 않는다(권장).
- **M-3** 기록 필드: 제작이 승인되면 `topics` 에 `used = true`, 구간, 후킹 대사, 제목, 결 태그를 저장한다.
- **M-4** 제작 기록이 없는 상태에서 모드를 요구받으면 "아직 기록이 없어 `새 소재`로 진행합니다"라고 알린다.
