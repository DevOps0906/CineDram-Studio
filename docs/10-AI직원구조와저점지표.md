# 10. AI 직원 구조 · 저점 지표 · 외부 분석 도구 (v10)

전달받은 화면(채널 성과 2건, 완성 영상 4편, "AI = 회사 직원" 슬라이드, 모델·노력 선택 화면) 분석을 반영한다.
**수치는 전달값이며 내가 검증한 것이 아니다.** 한 채널 사례라 목표값으로 쓰지 않는다.

## 1. 성과 비교 (전달값)

| 지표 | 채널 A (9/29~10/26) | 채널 B (같은 기간) | 후킹타임 (9/30~10/30) |
|---|---|---|---|
| 조회수 | 35,984,677 | 79,587,563 | 44,076,329 |
| 예상 수익 | ₩5,740,883 | ₩13,042,159 | ₩7,920,181 |
| 1,000회당 수익 | 약 160원 | 약 164원 | 약 180원 |
| 일평균 수익 | 약 20.5만 | 약 46.6만 | 약 28.3만 |
| 구독자 증가 | +1.6천 | +2.8천 | +1.7천 |
| 조회당 평균 시청 | 약 21초 | 약 21.5초 | 약 21.4초 |

내가 다시 계산해 본 것:
- 1,000회당(B): 13,042,159 ÷ 79,587,563 × 1,000 ≈ **164원** ✓. 일평균(A, B)은 28일 기준과 일치 ✓.
- **후킹타임 일평균 28.3만은 28일로 나눈 값**이다. 기간이 9/30~10/30(31일)이면 7,920,181 ÷ 31 ≈ **25.5만**. 기간 정의 확인 필요.
- 10/26 기준 160원대, 10/30 기준 180원대 → **수익 반영 지연** 해석과 일치. 최근 7일 수익은 과소 집계로 취급(docs/08 §6).
- 조회당 평균 시청 약 21초는 세 채널 공통. 영상 길이(24~74초)별 완주 구조를 데이터로 검증 대상으로 둔다 → 승인함에 **영상 길이 기록**.
- 구독 전환율은 매우 낮다(약 0.0035~0.004%) → 추천 의존 구조.
- 사업 계획에는 평균을 쓰고 고점(일 50만 등)은 쓰지 않는다.

## 2. "저점이 올라간다"를 지표로

| 지표 | 정의 | 용도 |
|---|---|---|
| **저점** | 최근 N편(예 20편)의 **7일 조회수 하위 20%** 값(p20) | 규칙 개선이 하한을 올렸나 |
| 중앙값 | 같은 구간 중앙값 | 평균 왜곡 방지 |
| **실패율** | 7일 조회수 **3만 미만** 비율 | 기획점 효과 확인 |
| 규칙 버전별 저점 | `rule_version` 별 | 규칙 개정 효과 |
| 타율 | docs/08 §7 | 기준 넘은 편 비율 |

- 3만·10만 같은 **기준값은 강의 수치이며 임시**다. **우리 채널 첫 20편**으로 정한다.
- 같은 **게시 후 경과일(7일)** 로 비교한다.
- 첫 20편 기록 양식: `data/first20_template.csv`.

## 3. 완성 영상 4편에서 확인한 것 → 반영

| 관찰 | 반영 |
|---|---|
| 4편 모두 L1 레이아웃(제목 2줄, 중앙 영상, 하단 `드라마 <작품명>`) | 채널 기본 템플릿 고정(`hookingtime`) |
| 제목 꼬리: `~의 최후 ㄷㄷ`, `~한 진짜 이유`, `~건드린 대치맘 대장` | 꼬리 4종 → **6종**(`~한 진짜 이유`, `~한 대장` 추가) — `rules/channel-hookingtime.md` |
| 3편에 `일타강사` 포함 | 작품·직업 키워드를 제목에 넣는 패턴 → `황금키워드` 필드로 관리 |
| 슬라이드 304만 vs 스튜디오 3,067,665회 | 같은 영상의 시점 차 → 슬라이드 수치는 캡처 시점 값 |

## 4. "AI = 회사 직원" 구조 매핑

| 슬라이드 | 의미 | 우리 시스템 |
|---|---|---|
| 말귀 알아듣는 빠른 직원 | 지시를 구체적으로 | `SKILL.md` 절차 |
| 요금제 = 월급 | 고정비 | §6 비용 비교 |

## 5. 단계별 모델·노력 배치 (초안 — 설정값으로 둔다)

| 단계 | 난이도 | 담당 | 노력 |
|---|---|---|---|
| 규칙 개정, 기획점 분석(주 1회) | 최고 | Fable 5.1 | 높음 |
| 소재 후보 3개, 흐름 4줄, 후킹, 제목 | 높음(품질 결정) | Opus 5.5 | 중간~높음 |
| 자막 전체 읽기, 줄거리·갈등 목록 | 중간 | Sonnet 5.5 | 중간 |
| 맞춤법 검사, 점검표, 자막/TTS 포맷 정리 | 낮음 | Haiku 5.5 | 낮음 |
| **SRT 재계산, 컷 길이, 크롭 좌표, 규칙 위반 검사** | 계산 | **스크립트(`shortsflow.py`)** | — |

- **계산은 모델에 맡기지 않는다.** 같은 입력 → 같은 결과, 비용 0원. 이미 `check`·`recalc`·`tts-measure`·`render` 가 이 역할을 한다.
- 노력은 중간 기본. "최대"는 사용량이 3.5배 이상 든다고 표시되므로 품질 차이가 데이터로 확인될 때만 올린다.
- **모델 이름·요금은 바뀐다 → 코드에 박지 않고 설정값**(`model_plan`)으로 둔다.
- 이 배치는 제안이다. 사용자의 전역 규칙(Claude 팀원 위임 시 Opus 우선 등)과 충돌하면 사용자 규칙을 따른다.

### `llm_calls` (모델별 타율 측정)

| 필드 | 내용 |
|---|---|
| job_id, step | 작업, 단계(소재/제목/줄거리/포맷 …) |
| model, effort | 모델, 노력 |
| tokens_in/out 또는 사용량 | 사용량 |
| result_ref | 산출물 경로, 사람 수정 여부(`human_edit`) |
| rule_version | 당시 규칙 버전 |

소재·제목 단계를 Opus와 Sonnet으로 나눠 돌려 **타율이 비슷하면 싼 쪽**을 쓴다. `tts_clips.credits_used` 도 함께 기록.

## 6. 비용 대비 수익 (월 30만 원 요금제 — 전달값)

| 채널 | 28일 예상 수익 | 요금제 비율 |
|---|---|---|
| A | ₩5,740,883 | 5.2% ✓ |
| 후킹타임 | ₩7,920,181 | 3.8% ✓ |
| B | ₩13,042,159 | 2.3% ✓ |

- 요금제 비용은 수익의 2~5% 수준 → 변수는 **검수 시간, TTS·디스크, 권리 위험**이 더 크다.
- 예상 수익(세전, 지연 반영), 최고 구간이다. **안정적 월 수익으로 보지 않는다.**
