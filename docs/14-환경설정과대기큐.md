# 14. 환경설정 · 대기 큐

사용자 결정(2026-11-02)을 설계에 반영한 문서다. 업로드 방식 선택은 원클릭 폼에서 **환경설정**으로 옮기고, 여러 영상을 동시에 만드는 **대기 큐**를 둔다.
업로드 정책 자체는 [docs/13 §13](13-원클릭제작흐름.md) 안 A가 정본이다. 여기서는 그 정책을 **어디서 켜고 끄는지**만 다룬다. 수치·외부 서비스 조건 중 확인하지 않은 것은 `미확인`으로 적는다.

## 1. 용어

| 용어 | 뜻 |
|---|---|
| 환경설정 | 계정 · AI API · 업로드 방식 3개 탭으로 된 설정 화면(구글 계정 탭은 채널 관리와 겹쳐 삭제, 사용자 지시 2026-11-02) |
| 채널 관리 | 사이드바 독립 메뉴(S-CH1). 구글 계정 연결·채널 등록·해제·제거는 **여기서만** 한다 |
| 구글 계정 | 사용자가 OAuth로 연결한 구글 계정. 여러 개 등록 가능 |
| 채널 | 구글 계정 아래의 YouTube 채널. **채널 단위**로 따로 등록·관리 |
| 업로드 방식 | 채널별 값. 전역 기본은 `검수 후 업로드`로 **고정**. `자동 예약`은 채널별로만 켜고, 안 A 조건과 §6-1 잠금을 모두 통과해야 함 |
| 대기 큐 | 제작 작업(`jobs`)이 자동 처리 차례를 기다리는 목록 |
| 슬롯 | 동시에 자동 처리할 수 있는 작업 자리. **LLM 단계 슬롯**과 **GPU·ffmpeg 슬롯**(1개 고정)으로 나눈다(§4, 제안). 사람 게이트를 기다리는 작업은 슬롯을 차지하지 않음 |

## 4. 대기 큐 규칙

`queue_state`는 작업 상태([docs/01 §2](01-상태머신과데이터모델.md))와 별개의 **실행 차례** 표시다.

정본은 **제작 서버 동시 실행 1**(GPU 받아쓰기·인코딩 충돌 방지, [docs/01 §1](01-상태머신과데이터모델.md)). 사용자의 "동시 제작"은 아래처럼 제안한다(**사용자 확정 대기**).

| 슬롯 | 쓰는 단계 | 개수 |
|---|---|---|
| LLM 단계 슬롯 | 대본·제목 초안, 장면 맞추기 등 AI 호출 | 여러 개(기본값 `미확인`) — 병렬 |
| GPU·ffmpeg 슬롯 | 받아쓰기, TTS 실측, 렌더 | **1 고정** — 직렬 |

| `queue_state`(제안) | 뜻 | 슬롯 | 작업 상태와의 대응 |
|---|---|---|---|
| `waiting` | 자동 처리 차례 대기 | 비점유 | `queued`, 또는 자동 단계 진입 직전 |
| `running` | 자동 처리 중 | **점유**(단계에 맞는 슬롯) | `matching`, `topic`의 자동 구간(받아쓰기·초안), `building` |
| `held_human` | 사람 게이트 대기(관문 ①②, 기획 승인, 승인함) | 비점유 | `topic`(선택·승인 대기), `review` |
| `held_resource` | 자원 제약 대기(디스크, AI 한도, 업로드 쿼터) | 비점유 | `blocked_disk`, `blocked_auth` 등 |
| `paused` | 사람이 일시정지 | 비점유 | 상태 유지 |
| `finished` | 큐에서 빠짐 | 비점유 | `done` / `failed` / `canceled` |

- **같은 작업 중복 실행 금지:** 조건부 UPDATE(`queue_state = 'waiting'`인 행만 `running`으로)로 한 작업자만 한 행을 집는다. 한 `job_id`는 동시에 슬롯 하나만 점유한다.
- **승인 해시와의 관계:** 슬롯을 잡을 때마다(재시도 포함) 기획 승인 해시가 현재 컷표와 같은지 다시 검사한다(P0-2, 엔진 `gate`). 다르면 `held_human`(재승인 대기)으로 보낸다.
- **취소의 의미는 상태마다 다르다:** `queued`·`running` → 작업 중지. `scheduled` → 플랫폼에 올라간 예약 영상 삭제가 필요하므로 **사람 확인 후** 원격 삭제.
- 일괄 제작 N개([docs/13 §12](13-원클릭제작흐름.md))는 `jobs` N개로 큐에 들어간다(1:N).
- 순서 변경은 `priority`만 바꾼다. 취소는 `canceled`로, 재시도는 `failed → queued`([docs/01 §2](01-상태머신과데이터모델.md)).
- 큐 흐름도: [diagrams/queue-flow.mmd](diagrams/queue-flow.mmd).
- 큐는 업로드를 하지 않는다. 업로드 예약은 승인함 [승인] 뒤 채널의 `upload_mode`에 따른다(docs/13 §13 안 A).

## 5. 보안·비밀 규칙

[AGENTS.md](../AGENTS.md) 절대 규칙("비밀 커밋·로그 금지", "업로드·`approve`는 사람만")을 따른다.

| 로컬 서버 | 8765·8766([docs/01 §1](01-상태머신과데이터모델.md))은 `127.0.0.1`에만 바인딩. Host·Origin 헤더 검사(DNS 리바인딩 방지), 세션 CSRF 토큰, **키를 평문으로 돌려주는 엔드포인트 금지** |

| 첫 업로드 잠금 | 새 채널, 첫 업로드 전 채널은 `자동 예약`을 켤 수 없다(첫 업로드는 반드시 사람 승인, [docs/08 §3](08-보관함과성과와타율.md)) |

### 6-2. 중복 업로드 방지
| 규칙 | 내용 |
|---|---|
| 상태 | `uploading` 신설([docs/01 §2](01-상태머신과데이터모델.md)): 업로드 세션 URI(resumable)와 `video_id`를 저장 |
| 재시도 | `uploading` 상태이거나 `video_id`가 있으면 **자동 재시도 금지**, 사람 확인 |
| 멱등 | videos.insert에 멱등 키가 있는지 — **확인 필요** |

### 6-3. 토큰 만료·폐기
| 규칙 | 내용 |
|---|---|
| 갱신 실패 | `blocked_auth` 상태 + 알림, 그 채널 업로드 보류 |
| 연결 해제 | Google 토큰 폐기(revoke) + 로컬 삭제 + 해당 채널 예약 보류 |

### 6-4. AI 비용 한도
제공자별 **일·월 한도, 작업당 상한, 재시도 상한**을 둔다(값 `미확인`). 넘으면 큐를 멈추고 `held_resource`로 보낸다. 호출 기록 `llm_calls`는 아직 ❌([docs/00 §15](00-통합설계서.md)).

| 항목 | 내용 |

| 다루는 데이터 | AI API 키, 구글 OAuth 토큰, 채널 정보, 원본·자막(외부 AI API·Aside로 전송 — 외부 서비스 노출, [docs/13 §6·§15-16](13-원클릭제작흐름.md)) |
| 필요한 키·권한 | AI 제공자 키(사용자 소유), YouTube 스코프(최소, 단계 6에 업로드) |

## 7. 로드맵 위치 ([docs/00 §13](00-통합설계서.md))

**기획·시안은 전체(환경설정 3탭 + 채널 관리 + 큐)를 그리고, 구현 순서는 단계별로 나눈다**(사용자가 시안·기획 전체를 요청함).

| 단계 | 구현 범위 |
|---|---|
| 1 | 대기 큐(GPU 슬롯 1, LLM 슬롯 병렬 여부는 확정 대기), 계정 설정 최소, AI 키 1종 |
| 2~3 | 큐를 제작 현황·승인함과 연결, AI 키 나머지 |
| 6 | 채널 관리(S-CH1: 구글 계정·채널 연결), 업로드 방식 탭, 업로드 예약 연동, §6 외부 계약 확인 |
